# Impact

Генератор нагрузки на Go для текстовых TCP-серверов. Отправляет команды из JSON-сценария через несколько соединений и измеряет частоту ответов, ошибки и задержки p50/p95/p99.

## Запуск

Нужен Go 1.22 или новее. Из каталога проекта:

```bash
go build -o impact .
./impact run scenario1
```

Сценарий читается из `scenarios/scenario1.json`.

## Сценарий

```json
{
  "target": "127.0.0.1:8080",
  "connections": 100,
  "duration": "30s",
  "timeout": "2s",
  "cleanup_timeout": "2m",
  "prepare": {
    "template": "SET {{key}} {{value}}",
    "count": 10000
  },
  "commands": [
    {"template": "GET {{key}}", "weight": 80},
    {"template": "SET {{key}} {{value}}", "weight": 15},
    {"template": "DEL {{key}}", "weight": 5}
  ],
  "cleanup": {
    "template": "DEL {{key}}"
  }
}
```

- `connections` — число одновременных соединений во время нагрузки.
- `duration` — время нагрузки; `timeout` — таймаут подключения и запроса.
- `cleanup_timeout` — общее время, отведённое на очистку.
- `prepare` — команда подготовки и количество ключей.
- `commands` — шаблоны нагрузки. Вероятность выбора равна `weight / сумму весов`.
- `cleanup` — команда удаления каждого созданного ключа.

Impact не знает значения команд. Подставляет `{{key}}`, `{{value}}` и `{{run_id}}`; ключи и значения уникальны для запуска. Клиенты случайно выбирают ключ из подготовленного набора и ждут ответ перед следующим запросом.

## Очистка

После нагрузки, Ctrl+C или ошибки подготовки Impact пытается удалить весь набор ключей. Подготовка и очистка не входят во время нагрузки.

До первого запроса список данных сохраняется в `runs/<run-id>.json`. Если очистка не завершилась или процесс аварийно остановлен:

```bash
./impact cleanup <run-id>
```

После успешной очистки файл запуска удаляется. Команда очистки должна допускать повторное удаление отсутствующего ключа.

## Ответы и ограничения

Запрос и ответ должны заканчиваться `\n`. Максимальный ответ — 1 MiB. HTTP и бинарные протоколы пока не поддерживаются.

По умолчанию любой полный ответ считается успешным. Для проверки добавьте `"expect_prefix": "нужный префикс"` в `prepare`, `cleanup` или элемент `commands`. Без этой проверки ответ с ошибкой также считается успешным, в том числе при очистке.

Задержки измеряются с шагом 1 мс; значения от 10 секунд попадают в последний интервал. При сетевой ошибке клиент нагрузки прекращает работу.
